# 个股复核细则与输出示例

本文件是 [Personal CIO 个股复核技能](SKILL.md)的按需参考，不是另一个技能。涉及计划、草稿或日志入库时，回到技能入口和仓库的正式模型，不能把本文件的分析模板当作导入格式。

## 按任务选择深度

| 请求 | 先回答 |
|---|---|
| 大盘或个股急涨急跌 | 截至何时、相对哪个基准涨跌多少？是大盘、行业还是个股因素？哪些催化已证实，哪些只是推断？变化影响长期现金流和业务风险，还是主要影响市场定价与流动性？ |
| 长期质量或估值 | 公司靠什么赚钱、护城河有多持久？当前价格隐含什么预期？在哪些事实下应改变长期论点？ |
| 持仓、建仓、重新入场、减仓或退出 | 账户是否允许？日线方向、持仓和风险是否支持？触发、失效、执行价格条件及最坏情境分别是什么？ |
| 交易纠偏 | 错在论点、时点、仓位、执行还是市场状态？哪些新证据支持改计划，而不是补偿前一笔亏损或错过的行情？ |
| 事后复盘 | 当时知道什么、决定了什么、实际上做了什么？分别评价决策、执行和结果，不用盈亏倒推过程质量。 |

## 长期质量与估值

- **生意与护城河**：谁付钱、为何选择这家公司、需求是经常性还是周期性的。根据行业核验转换成本、网络效应、品牌、成本、规模、知识产权、监管或渠道等优势。说明护城河的证据、变化方向和潜在破坏因素，不只列标签。
- **增长和财务**：区分有机增长与并购；看份额、产品和地域空间。按行业选择利润率、自由现金流、现金转化、资本回报、债务、周期和股权稀释。没有适用或可比口径时说明原因。
- **管理层与预期**：检查资本配置、并购和回购效果、研发投入及历史指引可信度。优先比较悲观、基准、乐观情景下的增长、利润率或现金流；估值指标用适合行业的口径，不只用市盈率，也不把单一目标价当成结论。
- **论点失效**：写下可观察的反证，如份额持续下滑、利润率结构性恶化、产品转换失败、资产负债表恶化或监管变化。结论可以是「论点完整」「削弱」「失效」或「证据不足」；这些是分析标签，不是系统状态。

## 结构、事件与仓位

- 当技术结论依赖 MA5/10/20/30/50/100/200、ATR、RSI 或成交量时，写明样本是否足够、用的是原始还是复权价格。对比基准时对齐区间和价格口径，避免把仅价格涨跌当成含分红收益。
- 缺口可研究是否源于消息重定价、趋势延续、衰竭或恐慌；这些是描述。写入 `gap_type` 时只能用正式枚举 `NONE`、`BREAKAWAY`、`EXHAUSTION`、`SHAKEOUT`、`PANIC`。正式 `market_regime` 只有 `TREND_UP`、`TREND_DOWN`、`RANGE`、`HIGH_RISK`；不明则留空，不把高波动直接翻译成 `HIGH_RISK`。
- 评估假跌破时，检查支撑或 MA200 被跌破后是否收复、下影线和成交量是否支持、是否出现后续确认。盘中单次跌破与连续收盘跌破不同。对照过往下跌日的量、近期均量和收盘在区间中的位置，不把放量单独当成买卖信号。
- 财报、指引、FDA 或其他监管决定、产品发布和宏观事件只在相关时展开。事件表没有记录不代表已核验。写清已知日程、出处和覆盖窗口，不为好看的技术图形跳过事件风险。
- 估算仓位和可承受亏损时，说明单账户净值、拟议价格和失效距离，另查组合敞口；缺数据时不给确定股数。交易计划的 `position_size.percent_of_portfolio` 是百分点，账户及组合权重、配置比例通常是小数。以[文档 04 的字段定义](../docs/04_Database_Design.md)为准。
- Vanguard 的 VOO/QQQ 可以按趋势和风险比较，过去讨论的 VOO 市值与 QQQ 市值比约 `0.5–1.5` 只是观察范围，不是硬约束、买入信号或默认置换权重。没有明确分配时，保留 `replacement: null`，不自动采用 70/30 或 60/40。

## 发现错误后怎样修正

| 可能的错误 | 复核重点与下一步 |
|---|---|
| 论点错误 | 重新核对基本面反证；按账户和保护性规则评估减仓或退出，不靠短线反弹修复长期论点。 |
| 时点错误 | 论点仍在时，等待结构和事件证据。止损后再入场是一笔新决策，需要新触发和新失效条件。 |
| 仓位错误 | 用账户净值、可承受风险和组合敞口重算，不依赖价格回升解围。 |
| 执行错误 | 区分追价、限价失当、止损距离与正常波动；先复核策略和结构，不为追回损失立刻反手。 |
| 市场状态改变 | 先重新分类，再选择策略。不要把震荡下的工具直接搬到趋势破位情境。 |

主动想法还要问：「为什么不是持有 VOO 或 QQQ？」把关注频率、盘中操作、事件暴露和维护复杂度写进比较；没有清楚优势时，保持观察是有效结果。复盘时保留原始理由、用户决定、执行价格与时间；样本不足的后续结果明确留空。

## 建议的交付格式

短答默认给判断、依据、失效证据和下一次复核点。完整报告可用以下层次，不必对每次请求机械套用：

1. **结论**：标的、数据时间、变化、账户和行动建议，以及最重要的风险。
2. **证据**：持仓角色、基本面与估值、日线与小时结构、主动想法相对基准的依据。
3. **条件方案**：入场或退出触发、失效条件、仓位口径、事件风险、纠偏与再评估条件。
4. **待核验**：缺失的数据及它如何改变结论。复盘另写实际成交和后续结果，分开给过程评价。

需要结构化摘要时，可补以下合成示例。它是聊天侧复核结果，不是可写入的 `TradePlan`、`DailySignal` 或审批记录。建议字段沿用英文标识符，内容用中文。

```yaml
symbol: EXAMPLE
data_as_of: null
account_id: null
account_role: null
action: WATCH
confidence: null
market_regime: null
reason: 尚无可核验的同日小时确认与账户风控证据。
entry_condition:
  - 核验已收盘日线和所需小时确认。
invalid_condition:
  - 核验后日线结构不再支持入场，或出现财报禁入事件。
repair:
  - 补齐证据后重新评估，不沿用本次观察结论生成草稿。
key_unknowns:
  - 账户归属、持仓、可交易现金及组合敞口。
  - 行情时效与财报覆盖窗口。
```
