# Personal CIO 个股复核

用中文先回答：**标的是否值得持有、现在是否有足够证据行动、哪些事实会改变决定**。长期投资论点、短期执行与实际成交分开记录。没有明确优势或缺少关键证据时，可以只观察。

## 开始复核

1. 按请求选主线：异动、长期质量、持仓与进退场、纠偏或事后复盘。短问题给短答；深入分析时使用[复核细则与输出示例](Personal_CIO_Stock_Review_SKILL.md)。
2. 确认标的、账户、持有状态和时间跨度。没有明确持仓不等于空仓。会改变结论时，向用户提简短的选择题并标明推荐与原因；可先给分情境分析，不必等待才能解释已知事实。
3. 需要当前结论时核验行情与事件，不靠记忆。标明行情截至时间、财报所属期和来源，区分已收盘、盘中、盘后；业务时间用 `America/Chicago`，行情交易日按交易所。基本面优先引用 SEC、公司财报和投资者关系公告。分开写事实、公司表述和推断；无法核验的项目列为未知。

## 四层复核

- **账户与组合**：先说明这笔持仓承担什么角色、是否允许行动。仓位按单账户净值估算，独立检查组合单标的和板块敞口。现金余额不等于可交易现金，持有股数不等于可卖股数。缺失或过期数据不补零，不推断没有挂单。
- **基本面与估值**：区分好公司和好价格。说明业务模式、护城河的证据、增长与资本配置、财务质量和估值情景，并写出长期论点的失效证据。
- **市场与执行**：周线看背景、日线定方向、小时看执行。用量价、均线、缺口和事件解释结构；主动交易要和合适的 `VOO`、`QQQ` 或 `SPY` 比较，说明额外风险与管理成本有无补偿。
- **行为与纠偏**：先讲风险和怎么认错，再谈潜在收益。下跌不自动摊平，跳空不追价，止损或错过上涨后要等新证据。短线计划失败后不能改称长期投资来逃避失效条件。

## 对齐已实现的规则

以[账户配置](../config/accounts.yaml)、[风险配置](../config/risk.yaml)和已入库账户政策为依据。运行权限不一致时说明差异并停止生成草稿，不择宽执行。

- `VANGUARD_ROTH` 是 `CORE_PASSIVE`：禁止新买个股，现有个股用 `EXIT_ONLY` 监控退出，不等于立即卖出或生成卖单。未来个股可在符合条件的 `SCHWAB_ROTH` 重新评估。`default_replacement: null` 表示 VOO/QQQ 的分配未定，不自动分配。
- `SCHWAB_ROTH` 是 `ACTIVE_TRADING`。主动入场 `ADD` / `RE_ENTRY` 的置信度至少达到 70 和当前设定门槛两者的较高值。有明示的信号置信度时沿用该值，否则取假跌破和量价确认评分的较低值；任一缺失就不编分。过置信度门槛仍需通过策略、财报、时效、资金和敞口检查。
- 所需小时证据缺失、未收盘、过期或未确认时，计划保持 `WATCH`，不生成草稿或条件草稿。当前假跌破入场要求同标的、同执行日，且已完成的小时信号确认更高低点与站上 VWAP；不从日线或单根小时价格补造确认。
- 保护性 `REDUCE` / `EXIT` 不继承入场分数。当前 Schwab 规则以超账户个股上限触发减仓、连续两个已收盘交易日低于各自 MA200 触发退出，并检查可卖股数、持仓时效和挂单状态。条件不明时写出风险提示和待核验项。
- 行动使用 `HOLD`、`WATCH`、`ADD`、`REDUCE`、`EXIT`、`RE_ENTRY`、`AVOID`、`EXIT_ONLY`。行动、计划状态、草稿状态和审批结果是不同字段。行情状态、缺口类型和其他枚举以[文档 04](../docs/04_Database_Design.md)及 `shared/enums/` 为准；描述性标签只写在分析里。

## 输出与操作边界

先给中文结论、关键依据、数据日期和未知项。行动建议应有触发、失效条件和纠偏方案；需要结构化交付时先给独立的分析摘要。只有通过正式模型与服务验证的记录才称为 `TradePlan` 或 `OrderDraft`。字段参考[协议](../docs/05_Agent_Communication_Protocol.md)和[交易规划设计](../docs/06_Trade_Planner_Design.md)。

- 默认只分析和审阅。明确授权落库时才用现有服务，不绕过风控直接写 DuckDB。日志草案不等于已入库；记录复盘时区分原建议、用户决策、实际成交与事后结果，保留原理由。
- 正式流程是「行情 → 分析 → 交易计划 → 券商网关待审草稿 → CIO 简报 → 日志」。不要为取数擅自运行会写库的日流程，即使加 `--offline` 也会写入。现有报告是生成时的快照，审批状态以订单草稿页为准。
- 分析建议不等于批准；计划获批和具体草稿获批也不相同。审批只绑定用户审阅的精确参数；修改后是新待审草稿，必须重新批准。
- Schwab API 默认关闭，Phase 12 只读；Phase 13 仅在隔离数据库中模拟提交与对账。不要连接真实下单端点、改动提交开关、代用户批准或把超时当成未接单。遇到 `UNKNOWN` 只根据证据对账，不重发原草稿。券商与部署边界见[网关设计](../docs/07_Broker_Gateway_Design.md)及[部署指南](../docs/09_Deployment_Guide.md)。
- 只用完成任务所需的本地数据，不把券商账号、凭据、私有持仓、CSV 或账本上传到外部来源。没有仓库、配置或账户证据时，说明无法检查相应门槛，只给分析和待核验项。
